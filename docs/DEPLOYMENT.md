# Deployment

The demo runs on three free tiers (TAD §11):

| Part | Host | Config in repo |
| --- | --- | --- |
| Web (React SPA) | **Vercel** | `apps/web/vercel.json` |
| API (Express) | **Render** web service | `render.yaml` |
| Database (PostgreSQL 16) | **Neon** | — |

```
browser ──▶ https://kiss-vtmp.vercel.app ──┬─ static files (SPA, /index.html fallback)
                                            └─ /api/* ──rewrite──▶ https://kiss-vtmp-api.onrender.com
                                                                       └──▶ Neon (pooled URL)
```

**Why the API sits behind the Vercel rewrite.** The refresh token is an `httpOnly`,
`Secure`, `SameSite=Strict` cookie (ADR-05). Browsers only send a Strict cookie to the same
site the page came from. Proxying `/api/*` through the web host keeps one origin, so the
cookie works, and CORS doesn't come into play.

## Accounts you need

All three have free plans and let you sign in with GitHub. One person creates them, then
invites the other as a team member.

1. **Neon**: https://neon.tech
2. **Render**: https://render.com
3. **Vercel**: https://vercel.com

## One-time setup

### 1. Database (Neon)

1. Create a project named `kiss-vtmp`, region **AWS Asia Pacific (Singapore)**, Postgres 16.
   Name the database `vtmp`.
2. Open **Connection details** and copy two strings:
   - **Pooled** (host contains `-pooler`). Add `&pgbouncer=true` to the end. This is
     `DATABASE_URL`.
   - **Direct** (pooling switched off). This is `DIRECT_DATABASE_URL` and is used only for
     migrations.

### 2. API (Render)

1. **New → Blueprint**, pick this GitHub repository. Render reads `render.yaml`.
2. Keep the service name **`kiss-vtmp-api`**. The web rewrite points at
   `https://kiss-vtmp-api.onrender.com`. If Render gives a different URL, update
   `destination` in `apps/web/vercel.json` to match.
3. Fill in the variables marked *sync: false*:
   - `DATABASE_URL`: the Neon pooled string
   - `DIRECT_DATABASE_URL`: the Neon direct string
   - `PUBLIC_BASE_URL`: the final web URL, e.g. `https://kiss-vtmp.vercel.app`
   - `CORS_ORIGINS`: the same web URL
   `JWT_SECRET` and `REFRESH_SECRET` are generated by Render. Never copy them anywhere else.
4. Deploy. Every build runs `prisma migrate deploy` against the direct URL, then the service
   starts. Check `https://kiss-vtmp-api.onrender.com/health` → `{"status":"ok","db":"ok",…}`.

### 3. Seed the demo data (once)

Run this from your own machine against the **direct** URL. Choose a strong demo password,
because the site is public:

```bash
DATABASE_URL="<neon direct url>" SEED_PASSWORD="<strong demo password>" pnpm db:seed
```

(PowerShell: `$env:DATABASE_URL="…"; $env:SEED_PASSWORD="…"; pnpm db:seed`, then close the
terminal.) The seed is idempotent, so you can re-run it. Share the demo password only with the
team and examiners.

### 4. Web (Vercel)

1. **Add New → Project**, import this repository.
2. Set **Root Directory** to `apps/web`. Vercel picks up `vercel.json` for the
   install/build/output settings. Leave "Include files outside the root directory" on, since
   the web app imports `packages/shared`.
3. Name the project **`kiss-vtmp`**, so the URL is `https://kiss-vtmp.vercel.app`. No
   environment variables are needed, because the API base is the relative `/api/v1`.
4. Deploy, open the URL and sign in with a seeded account.

### 5. Freeze `PUBLIC_BASE_URL`

Certificate QR codes (Sprint 6) encode `PUBLIC_BASE_URL/verify/<code>`. Once it's set on
Render, **never change it** (BRD §14, TAD §15.1). If you add a custom domain later, keep the
`*.vercel.app` address working.

### 6. GitHub (CI smoke test of the live site)

In the repository: **Settings → Secrets and variables → Actions**:

- Variable `PUBLIC_BASE_URL` = the web URL
- Secret `E2E_PASSWORD` = the demo seed password

After that, every push to `main` runs the CI job **Smoke test the deployed site** (read-only
checks).

### 7. Keep it awake (optional, recommended before demos)

Render's free tier sleeps after 15 idle minutes, and the first request then takes about
30–60 s. A free UptimeRobot monitor hitting `https://kiss-vtmp.vercel.app/api/v1/health`
every 5 minutes keeps it warm (TAD §15.1).

## Releasing

Push or merge to `main`. Render and Vercel both deploy `main` automatically through their
GitHub integrations, and migrations run in the Render build before the new version starts.
Pull requests get Vercel preview URLs for the web app only, and those previews use the
production API.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| Signed out on every reload | The browser isn't sending the refresh cookie. The site must be opened via the Vercel URL, never the Render URL directly. |
| `401 INVALID_TOKEN` everywhere after redeploy | `JWT_SECRET` changed. Users just sign in again. |
| Many users get `429 RATE_LIMITED` | `TRUST_PROXY_HOPS` is wrong, so every request looks like one IP. It must be `2` (Render + Vercel). |
| Build fails at `migrate deploy` | `DIRECT_DATABASE_URL` is missing or is the pooled URL. |
| `CORS` errors | Only appear if the page calls the Render URL directly. Use the rewrite (relative `/api/v1`). |

## Security checklist

- [ ] Secrets only live in the Render dashboard. `.env` is git-ignored.
- [ ] Demo seed password is not `Password@123`.
- [ ] Admin password changed after the first sign-in on production.
- [ ] `NODE_ENV=production` (Secure cookies, HSTS via helmet, trusted proxies).
